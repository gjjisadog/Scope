# Scope Analyzer 下一阶段功能扫描与优先级建议

> 基线：当前仓库 0.10.0 工作树，包含已完成的可靠性、录波一致性、状态机、性能以及 Live Capture 复用离线分析主线的改动。本文只做产品功能盘点和路线规划，不生成具体实施计划，不实现新功能。

## 1. 执行摘要

当前仓库已经越过“只能看离线 CSV”的阶段，形成了比较完整的单机波形工具骨架：离线大文件读取、多数据组叠加、多窗格、双光标、FFT/THD、序分量、PLL/dq0、派生曲线、标注导出、TCP/串口实时采集、软件触发、`.scope` 录波回放、模拟器和有限的 VS Code/JSON 桥接均已存在。

下一阶段的核心缺口不是再增加一个孤立分析算法，而是打通电力电子/DSP 工程师每天反复执行的四个闭环：

1. **看得见**：Live 时直接看到 RMS、峰值、峰峰值、实际频率和三相功率，而不是每次先冻结再离线计算。
2. **抓得住**：一次调试会话能够保留多个触发事件和 Capture，不被最后一次触发覆盖。
3. **存得下**：一个工程文件能够恢复数据源、布局、公式、光标、分析配置和 Live 配置。
4. **配得对**：开始采集前能判断通道数、格式、采样率、批大小和串口波特率是否超出链路预算。

因此建议把上述四项定义为 0.11.0 的 P0。Reference/Compare、连续 Live 电能质量、数学滤波、规则化 Pass/Fail、自动报告和滚动录波属于 P1；全频谱/时频、数字逻辑分析和更多格式属于 P2。多设备硬同步、远程固件升级、JTAG、复杂寄存器编辑器和完整设备控制平台暂不应进入核心路线。

## 3. 典型工程工作流与缺口

### 3.1 上电与闭环调试

工程师连接 DSP，选择母线电压、三相电流、调制量和状态位，先判断链路能否承受采样配置，再观察稳态 RMS、峰峰值、频率、P/Q/S/PF、THD 和 dq0。当前仓库能稳定采集和画波形，但“带宽是否安全”和“稳态指标是否正常”仍主要依赖人工估算及冻结后分析。

### 3.2 故障瞬态定位

工程师连续触发过流、母线跌落、锁相失败或状态位变化，需要保留多次事件，比较触发前后，筛选最严重的一次并生成报告。当前仓库只保留最后一个 Live Capture；`.scope` 虽可记录多个 trigger record，UI 没有事件历史和 Capture 导航。

### 3.3 算法版本回归

工程师把新旧固件或仿真/实机波形对齐，查看误差、超差时间、峰值偏差和相位差，再给出 Pass/Fail。当前仓库有多数据组叠加与基频相位对齐，但缺 Reference 角色、通道映射、通用事件/互相关对齐、差值、容差带和规则引擎。

### 3.4 长时间稳定性试验

工程师连续录波数小时，只在故障或越限时保留前后窗口，并希望按时间/大小分段、控制磁盘占用、快速找到录波。当前仓库的单文件手动录波可靠，但没有滚动分段、保留策略和录波库。

### 3.5 可复现分析与交付

工程师第二天重新打开同一调试任务，希望恢复所有数据、布局、光标、公式、通道映射、触发和导出设置，并能在 CLI/CI 中复跑规则和报告。当前仓库的多个配置文件是可复用预设，不是完整工程文件；JSON 桥只覆盖数据和单通道 FFT。

## 4. P0：下一版本必须完成

### P0-1 统一工程测量中心：实时 RMS/峰值/峰峰值/频率 + 三相 P/Q/S/PF

| 字段 | 内容 |
|---|---|
| 当前状态 | 已有 Y1/Y2/dY/min/max、dX/1/dX；已有点式 `pseqp/pseqq/rms3` 配方，但没有窗口化工程测量与三相功率仪表。 |
| 用户痛点 | 稳态调试时必须冻结、手算或导出到其他工具，无法快速判断过压、纹波、频率漂移、功率方向和功率因数。 |

| 典型使用场景 | 并网逆变器稳态验证、PFC 调试、电机电流纹波检查、DC/DC 上电和负载阶跃。 |

| SCP1 / `.scope` 影响 | **均不修改**；从现有样本计算。工程测量配置进入未来工程文件。 |

| 依赖关系 | 依赖统一时间窗口语义；三相功率依赖可靠通道角色和单位配置。 |

## 9. 分版本路线图

### 下一小版本：0.11.0——完成单机日常调试闭环

- 统一工程测量中心：RMS、平均、峰值、峰峰值、实际频率、P/Q/S/PF。
- Live/Offline/冻结 Capture 使用同一测量定义。
- 有界触发事件历史和 `.scope` TriggerRecord 导航。
- `.scopeproj` 工程文件、缺失文件定位、自动保存/崩溃恢复基础。
- 采集带宽与配置助手。

控制范围：不在 0.11.0 同时加入复杂规则、滚动录波、瀑布图或设备控制。

### 下一中版本：0.12.0——形成分析与对比工作台

- 连续 Live THD、序分量、dq0、PLL 频率/锁定质量。

## 10. 产品边界与决策门

建议继续把 Scope Analyzer 定位为：**面向电力电子与 DSP 的单机采集、录波、波形分析、对比验证和报告工具**。

以下能力只有满足决策门后才进入路线：

- 多设备硬同步：必须先有硬件时钟和固件协议所有者。
- 参数控制：必须先有设备无关或明确设备专用的参数 schema、安全等级和读回机制。
- 协议解码：必须有真实使用频度和目标协议优先级。
- 新数据格式：必须先有脱敏真实文件、元数据说明和验收样本。
- AI 自动化：必须建立在稳定 CLI/JSON/rules 上，AI 不直接成为算法真实性来源。
