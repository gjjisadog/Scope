# `.scopeproj` V1

`.scopeproj` 是 Scope Analyzer 0.11.0 引入的 UTF-8 JSON 工程文件。它引用原始 CSV、DAT、`.scope` 和 Capture 资产，不把原始波形样点嵌入 JSON，也不修改 SCP1 V1 或 `.scope` V1。

## 保存内容

- 主数据组和附加数据组、显示名、时间偏移与线型。
- 通道显示名、颜色、可见性、倍率、窗格和线宽。
- 布局、视口、光标和侧边面板状态。
- FFT、序分量、PLL/dq0、三相功率绑定和数学派生曲线。
- TCP/串口预设、采样率、批次、通道和触发配置；恢复时不会自动连接设备。
- Capture 引用、固定/选择状态、导出设置与标注。

内存 Capture 会写入 `<工程名>.scopeproj.assets/captures/` 下的普通 `.scope` V1 文件。移动工程时应同时移动该资产目录。

## 路径与恢复

每个源同时保存安全相对路径和绝对路径提示。打开顺序为：

1. 工程目录下的相对路径。
2. 绝对路径提示。
3. 用户选择的重定位文件。

所有必需数据源都会先解析并打开；只有全部成功后才替换当前工作区。打开失败不会破坏正在使用的工作区。文件大小变化会报告为元数据不匹配，但允许用户继续恢复可读文件。

## 写入和自动恢复

- 显式保存采用临时文件、同步落盘、备份交换和失败恢复。
- 显式保存和 Capture 资产写入在后台线程执行；工程菜单显示保存状态并允许取消。大 Capture 每个写入分块都会检查取消信号，取消后删除临时资产且不发布工程 JSON。
- 已保存工程在发生交互后每 30 秒写入独立的 `.scopeproj.autosave`。
- 打开工程时只考虑比显式工程更新的自动保存；无效自动保存会报错，不会静默载入或修改当前工作区。
- JSON 最大为 10 MiB；Capture 样点必须位于伴随 `.scope` 资产中。

## 兼容约束

- `scopeProjectType` 必须为 `scope-analyzer-project`。
- `schemaVersion` 当前为 `1`；未知版本会明确拒绝。
- ID、引用、有限浮点数、布局、通道绑定和相对路径均在恢复前校验。
